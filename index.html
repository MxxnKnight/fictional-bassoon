HOW TO
PUBLISH

Publishing is a file drop. No CMS. No login. You push a Markdown file, the board picks it up.

  1. Write your piece as .md in the /posts folder of your GitHub repo.
  2. Stamp it — start the file with frontmatter: title, file number, type, date, tags, status.
  3. List it — add the filename to /posts/manifest.json.
  4. Push. The board fetches from raw.githubusercontent.com on load. Done.

Field components

The markup supports everything a dossier needs:

  • ||spoiler|| — blurred text, tap to reveal
  • ![alt](img.jpg "spoiler: reason") — sealed image, tap to unseal
  • ![alt](img.jpg "filter: grayscale(1)") — image with CSS filters
  • ==redacted== — black-bar redaction
  • [[023-02]] — internal link to another file
  • :::timeline — vertical incident timeline
  • {% youtube ID %} / {% video %} / {% audio %} — embeds & themed player
  • ```lang — code box with copy button
  • :::box, :::tabs, :::collapse, :::section — structured blocks
  • > [!NOTE] — alert boxes (note, tip, important, warning, caution)
  • :badge[] :tag[] — badges & tags
  • [text](tooltip: tip) — hover tooltips
  • [Label](button:/path) — dossier buttons
  • - [ ] checklists, <kbd> keys, *** dividers
  • [^1] footnotes, :::memo callout boxes, pull quotes, tables, anchors on every heading

Full reference with live previews: open file 023-05, the Field Manual.

Point the board at your repo by setting REPO at the top of assets/js/app.js. Leave it empty to serve /posts locally.
